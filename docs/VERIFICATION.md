## 迁移与账号验证

- 根据 v1.0 的实际数据库结构迁移用户、进度和作业；保留账号密码、旧版本号、备注、附件内容、历史评分、课程快照及 AI 配置密文。
- 原账号成为管理员；第二个用户可拥有相同任务的独立版本和进度。
- 迁移前备份为 0600，数据库外键检查通过；重复启动不重复迁移。
- 不完整的原始数据触发回滚，旧表、记录和会话仍保留；未来版本数据库被拒绝启动。
- 原密码可登录迁移后的系统，旧作业与附件可读取，新提交版本接续递增。
- 用户 A 不能通过列表、详情、文件、评审或素材 ID 读取用户 B 的记录；不跨用户拼接仪表盘和进度。
- 学习者不能修改模型设置、测试服务连接或调用管理员管理接口。
- 初始密码强制修改；密码重置、停用、角色变更撤销会话。
- 验证密码后发生并发改密时，旧验证结果不能再签发新会话；改密后同时被管理员重置的情形也被拒绝。
- 用户额度与全站额度同时生效；并发提交不会覆盖版本。

## AI 素材与评审验证

- 素材 JSON 协议、必选种类、数量与长度；拒绝 NaN、重复键、CSV 列数异常和可能执行的公式。
- 拒绝绝对路径、越界路径、非法字符、系统保留文件名、大小写重复和文件目录冲突。
- 拒绝不能编码成 UTF-8 的模型输出，包括文件名、正文和包元数据中的孤立 surrogate。
- 模拟提供方完成排队到生成、预览内容、单文件和 ZIP 下载；ZIP 保留 manifest 与哈希。
- 相同进行中参数去重；新生成保留新版本；用户与全站额度、失败状态、重启状态和账号变更按约定处理。
- 素材归属和作业任务一致才允许关联；素材背景不加入学习者证据引用集合。
- 原评审结构、分数范围、证据原文匹配、服务端求和、失败无分数以及固定“运行未验证”标记继续通过。
- 本地 HTTP 模拟服务验证实际 Chat Completions 请求形状、Bearer 请求头、中文响应、usage 以及认证错误、限流、服务器错误、重定向和响应超限处理。

## 备份与前端验证

- 普通备份恢复原容器，升级备份保持停止；失败移除不完整归档并恢复原运行状态。
- 恢复原容器使用 start，不会因已构建新镜像而提前迁移。
- 错误 Compose 项目找不到原 app 容器时，不创建一个误导性的空数据备份。
- .env 的密钥在部署地址更新和备份过程中保留，私有文件权限为 0600。
- 前端切换账号会中断旧请求并丢弃迟到的私有响应。
- 旧会话迟到的 401 不会注销新账号；当前会话 401 会正常触发退出状态。

## 复现命令

在项目根目录，先按 README 安装开发依赖，再执行：

```bash
PYTHONPATH=backend .venv/bin/python -m pytest -q backend/tests tests
python3 scripts/validate_course.py
npm --prefix frontend test
npm run build
```

当前测试环境出现一条来自 Starlette TestClient 的 httpx 适配器弃用提示，115 项测试仍全部通过。前端安装期间的 npm 配置提示不影响锁定依赖的安装与构建。

## 仍需在目标服务器验收

1. **真实 Docker 镜像与数据卷操作。** 本次环境没有 Docker 引擎，没有执行容器构建、启动或真实卷备份恢复；备份流程测试使用受控的子进程替身。
2. **域名与 HTTPS。** 没有修改用户 DNS、反向代理或线上环境。
3. **真实 AI 服务兼容性与内容质量。** 模拟调用验证协议与失败处理；实际服务、模型能力、输出长度和收费由管理员配置后确认。
4. **完整登录后的浏览器交互。** 已通过类型、模板、构建和会话隔离测试，没有完成浏览器端到端流程实测。
5. **长期运行与容量。** 没有多用户负载基准或第三方安全审计；本版使用单应用进程、SQLite 及两个后台线程。

升级后建议按照 [升级指南](UPGRADE-v1.1.md) 的验收清单检查原账号和历史数据，再创建一个学习者，生成小型素材包并完成一次关联作业评审。测试结果不代表业务事实核验、代码运行认证或第三方模型评分一定正确。
