### 39 项测试覆盖的行为

- 账号初始化、关闭未配置的初始化入口、登录、退出、会话与 CSRF。
- 跨站/畸形 Origin 拒绝，错误输入的可控响应。
- 作业版本、附件下载鉴权、附件大小和类型限制、Python 代码不被执行。
- AI 密钥加密保存，公开接口不返回密钥；公网地址策略和内网拒绝。
- 评分项完整性、分数范围、服务端求和、伪造证据引文拒绝、固定运行未验证标记。
- 评审失败无分数、重新提交/评审、历史保存、应用重建后的数据持久化。
- 使用本地 HTTP 模拟服务验证实际 `/chat/completions` 请求、Bearer 认证头、中文 JSON、文本响应与 usage 解析，以及 401 / 429 / 500 / 重定向 / 超限响应处理。
- 真实内置 30 任务课程经过 API 读取，提交含 JSON 附件的作业、记录进度、重启并重新登录后仍可读取；未配置模型时拒绝评审，不制造分数。
- 修改部署地址不会自动轮换加密主密钥或初始化令牌。

## 仍需在目标部署上完成

1. **Docker 镜像构建和容器启动。** 本次环境没有 Docker 引擎，未执行 `docker compose up`；容器文件经过静态审查，应用本身通过原生运行与测试。
2. **域名、HTTPS 和反向代理。** 未访问用户服务器、修改 DNS 或安装站点。示例配置中的域名与证书路径需要按实际环境替换。
3. **真实服务商连接和评分质量。** 本次没有使用付费模型密钥。HTTP 模拟服务证明协议与异常处理可工作，不能证明任意服务商/模型兼容，也不能证明某个模型的评分准确性。
4. **登录后的完整浏览器流程。** 本次浏览器检查止于账号开通界面；未自动输入账号凭据。账号和学习流程经 API 集成测试验证，完整交互仍需在目标部署中检查。
5. **真实 Docker 备份恢复演练。** 备份与空卷恢复脚本经过代码/路径检查，但未在 Docker 数据卷上执行。首次部署后应创建少量测试记录，备份，再用新项目名和新端口恢复验证。
6. **容量和长期运行。** 未做多用户压测、长周期运行或第三方安全审计；当前设计是一个账号、一个后端 worker。

## 首次上线后的短验收流程

- 健康接口返回 `status:ok`，通过 HTTPS 创建账号、退出后重新登录。
- 课程显示 10 周 / 30 项实践；进入第一项任务可以阅读教程、量规和资源。
- 提交一段说明与一个 UTF-8 JSON 文件，确认新版本、静态检查和下载内容。
- 保存实际模型配置并测试连接；确认发送材料后评审，检查分项分数、原文证据和“未运行代码”的说明。
- 修改后提交新版本，确认旧版本和旧评审仍存在。
- 重启应用，确认账号、学习时间、提交与模型设置仍可使用。
- 使用独立项目名完成一次备份恢复，并核对上述记录。
