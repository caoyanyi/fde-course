# FDE 独立交付实战课

本目录提供学习平台使用的中文课程数据。主文件为 `curriculum.json`，版本 `1.0.0`。课程面向熟悉 PHP、Vue、数据库/服务器和 DevOps、已有模型 API 调用经验的全栈开发者，目标是独立承接范围明确的 AI 应用项目。

## 内容与投入

共 10 周、30 个任务、200 小时核心学习与实践，每周 3 个任务合计 20 小时。课时是建议投入，不是完成保证；可另留每周 0–4 小时机动。实际投入由学习者记录。

1. 定义问题并交付最小服务。
2. 让 AI 输出进入业务流程。
3. 建设可追溯的知识检索。
4. 检索评估与权限验收。
5. 受控工具与工作流。
6. 运行、部署与恢复。
7. 真实试用与反馈改进。
8. 迁移到业务报表场景。
9. 把技术能力转成可交付服务。
10. 最终验收与独立交付案例。

学习者开发的主项目是“工单与运维知识助手”，它与当前学习平台是两个不同项目。第 8 周用 12 小时迁移到只读业务报表场景，用另外 8 小时整理复用能力和完善主项目。课程不要求重学完整 PHP/Vue 基础，也不以模型训练、算法研究或无边界的自主执行为主线。

## 数据结构

根对象包含 `version`、`title`、`description`、`audience`、`totalWeeks`、`totalHours`、`weeks`。`audience` 为字符串。

每周包含稳定的 `id`（如 `week-01`）、`number`、`title`、`summary`、`goal`、`hours` 和 `tasks`。

每个任务包含：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `id` | string | 稳定任务 ID，例如 `w01-t01`，用于作业与进度关联 |
| `title` / `summary` | string | 标题与任务概述 |
| `hours` | number | 建议核心投入小时数 |
| `objectives` | string[] | 学习目标 |
| `tutorial` | `{title, body}[]` | 教程章节，`body` 为 Markdown |
| `steps` | `{title, description}[]` | 可执行的练习步骤 |
| `deliverables` | string[] | 要提交的产物与证据 |
| `acceptanceCriteria` | string[] | 验收条件 |
| `rubric` | `{id, title, weight, description}[]` | 评价维度；单任务权重总和为 100 |
| `resources` | `{title, url}[]` | 官方资料入口 |
| `prerequisites` | string[] | 前置任务 ID；当前采用线性学习顺序 |
| `submissionPrompt` | string | 提交时需说明的重点 |

前端应安全渲染 Markdown，禁用未经清理的 HTML，并把外部链接作为外部资源处理。课程数据中的示例代码用于学习，学习者应在自己的练习项目和测试环境执行。

## 评价与证据边界

AI 评价用于依照量表审阅学习者提交的文本、代码片段、文件与运行证据。课程不声称学习平台已实际执行用户代码、访问仓库、部署服务、验证外部地址或证明生产质量。缺少运行材料时，应明确标记“缺少证据”或提出补充要求，不能编造测试结果。

程序可确定的内容（字段结构、数字计算、权限拒绝、幂等、引用 ID 集合等）应优先由学习项目中的确定性检查验证；回答是否有据、是否帮助用户完成任务等，需要人工复核。AI 评分是辅助反馈，不是职业认证。权限泄漏、未确认的写操作等阻断问题，不得用平均得分抵消。

真实访谈、用户试用与模拟练习必须明确区分。课程中的样本数、时长与阈值为练习建议，不能被当成通用行业标准。外部服务价格和可用性需要在实际项目中重新确认。

## 更新与扩展

- 已存在的任务 ID 应保持稳定，避免历史作业失去关联。
- 修改核心任务要求或评分口径时更新 `version`，并保留变更说明；历史评审应保留所用课程/量表版本。
- 新任务的前置 ID 必须存在且不能形成环；当前所有前置均为之前的任务。
- 调整课时后同步周课时和根对象总课时。
- 每个任务至少保留 3 个教程章节、4 个操作步骤，以及明确交付物、验收条件和总权重 100 的量表。
- 官方资料链接按 2026-10-30 编写时所使用的入口组织；官方页面可能调整地址，维护时应检查链接与教程适用性。
- 若未来允许多个课程，不要复用相同任务 ID 表示不同内容；应增加课程标识和版本关联。

## 建议的内容校验

维护课程时检查：10 周、每周 3 任务、共 30 任务；每周任务课时合计 20，总计 200；任务 ID 唯一；前置任务存在且早于当前任务；每项量表权重为正且合计 100；必填数组非空；所有资源使用 HTTPS。

内容评审还应检查：步骤能否执行、交付物能否复核、教程是否将假设写成事实、是否错误声称已执行代码或取得真实客户成果。结构校验只能发现数据问题，不能替代人工检查教学质量。
